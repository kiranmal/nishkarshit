# Database: MySQL / MariaDB

The application stores everything in **MySQL 8 (or MariaDB 10.5+)**. MongoDB is no longer used at runtime; the `mongodb`
package remains only as a dev dependency for the one-time data import.

## Set up a new database
```
# 1. create an empty database (utf8mb4) and a user, e.g.
CREATE DATABASE nishkarsh CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'nis'@'%' IDENTIFIED BY '…'; GRANT ALL ON nishkarsh.* TO 'nis'@'%';

# 2. .env.local
DATABASE_URL=mysql://nis:…@host:3306/nishkarsh

# 3. create the tables, the first admin and the default content
npm run db:migrate
npm run seed:admin
npm run seed:cms
```
`migrations/001_initial_schema.sql` is the same schema as plain SQL (generated by `npm run db:schema`) if you prefer to
run it yourself (phpMyAdmin, cPanel, a DBA). `npm run db:migrate` is idempotent and also adds columns introduced by newer versions.

## Move your existing MongoDB data
```
# .env.local must contain BOTH the old MONGODB_URI/MONGODB_DB and the new DATABASE_URL
npm run db:migrate
npm run db:import-mongo -- --dry-run     # reads + converts everything, writes nothing
npm run db:import-mongo                  # copies; ids/dates/nested data are preserved
```
* Ids stay the same 24-character values, so admin URLs, references and logins keep working.
* Safe to re-run: rows that already exist are skipped (`--overwrite` replaces them).
* A per-table “mongo N → mysql N” count is printed so you can verify the copy.
* Recommended cut-over: stop admin editing → import → switch `DATABASE_URL` → smoke-test → keep MongoDB read-only for a week.

## How it is built
`src/lib/db/` is a small data layer that keeps the code's document-style API (`collection("x").find/updateOne…`) on top of SQL:
* `schema.ts` — single source of truth: every table, its typed columns (strings, ints, dates, booleans) and indexes.
  Nested content (sections, cards, SEO, galleries) lives in JSON columns; any field not listed is kept in the `extra` JSON column, so nothing is lost.
* `query.ts` — translates filters (`$or`, `$in`, `$regex`, `$exists`, …) into parameterised SQL (values are never concatenated).
* `collection.ts` — updates run as row-locked transactions (same atomicity as before); unique-key violations surface as the error code the app already handles.
* `ddl.ts` — generates `CREATE TABLE` from the schema. To add a field: add it to `schema.ts` (or just save it — unknown fields go to `extra`) and run `npm run db:migrate`.

## Hosting notes
* Managed MySQL that needs TLS: set `DB_SSL=true` (optionally `DB_SSL_CA`).
* Serverless hosting (Vercel): use a pooled/proxied MySQL endpoint and keep `DB_POOL_SIZE` small (e.g. 3–5).
* Text search (`$regex`) uses `LIKE` with a case-insensitive collation; slugs are unique case-insensitively.
